## 8.3 行为等价性验证（核心）

本测试层直接服务于 "100% 行为级复刻" 原则。参见 00 号文档第五章的完整方法论，此处给出具体测试实现指南。

### 8.3.1 工具 I/O 等价性测试

每个工具配套一个 `{ToolName}EquivalenceTest.java`，使用 JSON 夹具驱动：

```java
class BashToolEquivalenceTest {
    private final BashTool javaTool = new BashTool();
    private final Path fixtureDir = Path.of("tests/equivalence/tools");

    @ParameterizedTest
    @MethodSource("loadBashCases")
    void bashEquivalence(String caseId, JsonNode input, JsonNode expected) {
        ToolResult result = javaTool.execute(
            objectMapper.convertValue(input, BashInput.class),
            standardContext()
        );

        // 语义比对而非字符串比对
        assertThat(result.isError()).isEqualTo(expected.get("is_error").asBoolean());
        assertThat(normalizeVolatile(result.content()))
            .isEqualTo(expected.get("content").asText());
    }

    static Stream<Arguments> loadBashCases() {
        // 从 bash_cases.json 加载所有测试用例
    }
}
```

### 8.3.2 协议兼容性验证

```java
class ProtocolEquivalenceTest {
    // 15+ golden 文件，每个对应一个会话场景
    @ParameterizedTest
    @MethodSource("goldenFiles")
    void protocolMatchesGolden(Path goldenFile) {
        // 1. 解析 golden 文件中的场景定义（用户输入序列 + Mock LLM 响应）
        Scenario scenario = parseScenario(goldenFile);

        // 2. 运行 Java 后端，捕获 JSON-Lines 输出
        List<String> javaOutput = runJavaBackend(scenario);

        // 3. 逐行语义比对（跳过 volatile 字段）

        assertJsonLinesSemanticallyEqual(golden, javaOutput);
    }
}
```

### 8.3.3 Agent 循环等价性验证

```java
class AgentLoopEquivalenceTest {
    @Test
    void identicalToolCallSequenceForSameMockResponse() {
        // 1. 定义 Python 版已知的工具调用轨迹
        List<String> expectedToolSequence = List.of("glob", "grep", "file_read");

        // 2. WireMock 返回与 Python 测试相同的 LLM 响应
        stubLlmResponse("fixtures/agent_loop_3_tools.json");

        // 3. 运行 Java Agent 循环
        List<StreamEvent> events = PublisherAdapter.toList(
                engine.runQuery(testMessages, options));

        // 4. 提取工具调用序列，精确比对
        List<String> actualToolSequence = events.stream()
            .filter(e -> e instanceof ToolStarted)
            .map(e -> ((ToolStarted) e).toolName())
            .toList();

        assertThat(actualToolSequence).isEqualTo(expectedToolSequence);
    }
}
```

### 8.3.4 验证检查清单

每个 Phase 结束时必须通过：

- [ ] 该 Phase 涉及的工具全部通过 I/O 等价性测试（夹具数量 ≥ 工具类数 × 3）
- [ ] 该 Phase 涉及的 BackendEvent 子类型全部有协议 golden 文件覆盖
- [ ] Agent 循环回归：至少 3 个核心场景的 mock 轨迹对比通过
- [ ] 任何失败 case 在该 Phase 内关闭，记录根因和修复 commit

### 8.3.5 差异分类与处理策略

| 差异类型 | 判定标准 | 处理方式 |
|---------|---------|---------|
| 逻辑缺陷 | 工具返回不同结果、不同错误标志 | 必须修正 Java 实现 |
| 时序差异 | 并发工具执行顺序不同但各自结果正确 | 接受，记录为已知差异 |
| 环境差异 | 依赖 `/bin/bash`/macOS 特定行为 | 接受，标注平台要求 |
| 未定义行为 | Python 依赖未文档化的内部实现细节 | 评审决定以哪边为准，更新 spec |
| Volatile 差异 | 时间戳/UUID/PID 不同 | 接受，比对时跳过这些字段 |
