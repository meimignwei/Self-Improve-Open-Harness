## 5.1 总体架构

可观测性体系由三大支柱构成：

- **Metrics（指标）** — Micrometer + Prometheus：覆盖 Agent Loop、LLM API、工具执行、渠道/网关、记忆系统、Swarm 多智能体、JVM 系统级共 7 大类指标，通过 `/metrics` 端点暴露给 Prometheus 抓取。
- **Tracing（链路追踪）** — OpenTelemetry + OTLP Exporter：每个 Agent 会话 → 循环轮次 → LLM 调用 / 工具执行的 Span 层级结构自动关联，跨 Swarm 子进程和 MCP 服务器传播 Trace Context。
- **Logging（结构化日志）** — SLF4J + Logback + Logstash Encoder：JSON 格式输出，自动注入 TraceID/SpanID，支持控制台（开发）和滚动文件（生产）双输出。

三大支柱通过 OpenTelemetry 的 W3C Trace Context 实现关联：Metrics 的 Exemplar 指向 Trace，Log 的 trace_id/span_id 关联到 Span，Grafana 面板可从指标下钻到追踪再到日志。

## 5.3 Distributed Tracing 链路追踪

### 5.3.1 Span 层级结构

```
agent.session # 顶层：整个会话
└── agent.loop.iteration [turn=1] # 第1轮循环
    ├── llm.api.call # LLM API调用
    ├── tool.execute [name=bash] # 工具1执行
    └── tool.execute [name=file_read] # 工具2执行
```

### 5.3.2 Trace Context 传播

```java
/**
 * 跨进程 Trace 传播（用于 Swarm 子进程和MCP 服务器）。
 */
public class TraceContextPropagator {

    // 注入到子进程环境变量
    public Map<String, String> inject(Context context) {
        Map<String, String> carrier = new HashMap<>();
        GlobalOpenTelemetry.getPropagators()
                .getTextMapPropagator()
                .inject(context, carrier, Map::put);
        return carrier;
        // 结果：TRACEPARENT=00-<trace_id>-<span_id>-01
    }

    // 从环境变量提取
    public Context extract(Map<String, String> env) {
        return GlobalOpenTelemetry.getPropagators()
                .getTextMapPropagator()
                .extract(Context.current(), env, new MapTextMapGetter());
    }
}
```

## 5.4 Structured Logging 结构化日志

### 5.4.1 Logback 配置

```xml
<!-- logback.xml -->
<configuration>
    <!-- 控制台输出（开发环境） -->
    <appender name="CONSOLE"
              class="ch.qos.logback.core.ConsoleAppender">
        <encoder
                class="ch.qos.logback.classic.encoder.PatternLayoutEncoder">
            <pattern>%d{HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>

    <!-- JSON 结构化输出（生产环境） -->
    <appender name="JSON_FILE"
              class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_DIR:-logs}/openharness.json.log</file>
        <rollingPolicy
                class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>logs/openharness.%d{yyyy-MM-dd}.%i.json.log</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder class="net.logstash.logback.encoder.LogstashEncoder">
            <!-- 自动注入 TraceID / SpanID -->
            <provider
                    class="io.opentelemetry.instrumentation.logback.mdc.v1_0.OpenTelemetryAppender"/>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="JSON_FILE"/>
    </root>
</configuration>
```

## 5.5 健康检查

```java
/**
 * Kubernetes 兼容的健康检查端点。
 * 通过内嵌的轻量 HTTP 服务器暴露。
 */
public class HealthServer {

    // GET /health -- Liveness Probe
    public HealthStatus liveness() {
        return new HealthStatus("UP", Map.of(
                "jvm", checkJvm(),
                "disk", checkDisk()
        ));
    }

    // GET /ready -- Readiness Probe
    public HealthStatus readiness() {
        return new HealthStatus(allReady ? "UP" : "DOWN", Map.of(
                "llm_provider", checkProviderAuth(),
                "memory_store", checkMemoryDir(),
                "channels", checkChannels()
        ));
    }

    // GET /metrics -- Prometheus Metrics
    public String metrics() {
        return prometheusRegistry.scrape();
    }
}
```
